# 2027년 지원 준비를 위한 학습 계획

2026-09-22 수정. 전제는 컴퓨터공학과 3학년, 주 6~10시간입니다. 제공된 대화와의 [비교·선택 이유](../../../docs/curriculum_alignment.md)를 반영했습니다. 방학에 20~25시간을 확보하거나 2027년에 정규직 입사가 가능하다고 전제하지 않습니다. 실제 졸업·입사 가능 시기는 아직 확인하지 않았습니다.

## 준비 방향

먼저 Python·SQL·데이터 처리·백엔드의 공통 기반을 쌓습니다. **2027년 2월에 직접 해 본 작업과 지원 가능한 공고를 기준으로 데이터 엔지니어링·AI 서비스·금융 IT 중 주력 방향을 재검토**합니다. 연구 중심 머신러닝 직무는 공고에 따라 별도 연구 경험과 학력 조건을 확인합니다.

첫 프로젝트는 OrderLens입니다. 기본 기능의 코드가 이미 있어도 호준님이 학습을 완료했다는 뜻은 아닙니다. CSV 한 행과 테스트 하나부터 읽고 수정합니다. 두 번째 FinInsight는 첫 프로젝트를 직접 실행·수정·설명할 수 있고 시간 여유가 있을 때 시작합니다. 아래 월별 표는 이번에 조정한 제안이며, 원래 대화에서 복사되지 않은 표를 복원한 것이 아닙니다.

2027년 초 첫 시연이 가능해지면 인턴·학교 현장실습의 학년·졸업·근무 조건을 확인합니다. 두 프로젝트나 9월을 기다려야 지원할 수 있다는 의미가 아닙니다. 월말 기준을 충족하지 못하면 다음 기술을 추가하기보다 해당 단계를 반복합니다.

금융 IT가 주력이 되면 2027년 3~6월의 두 번째 프로젝트를 Java/Spring 모의 계좌·송금 시스템으로 대체할 수 있습니다. 잔액 부족, 중복 요청, 동시 송금, 롤백, 인증을 검증하고 RAG 범위를 줄입니다. 실제 돈을 이동시키지 않으며 세 번째 대형 프로젝트를 더하지 않습니다.

## 주 8시간의 예시

| 활동 | 시간 |
|---|---:|
| 프로젝트 구현과 디버깅 | 3시간 |
| Python·SQL 기초 및 연습 | 2시간 |
| CS·코딩테스트 | 2시간 |
| 코드 설명·회고 기록 | 1시간 |

6시간만 가능한 주에는 기능 규모를 줄이고 기초·복습을 유지합니다. 시험 기간에는 새 기술을 추가하지 않고 기존 코드 한 부분을 설명하는 짧은 과제로 바꿉니다. 1년 내내 같은 속도를 전제하지 않습니다.

## 단계 통과 기준

| 단계 | 직접 확인할 능력 |
|---|---|
| Python 기초 | CSV 한 행을 읽고 변환·예외를 설명하며 테스트 입력 하나 수정 |
| API 기초 | 파일을 보면서 요청 URL, 입력 검증, 함수 호출, 응답의 관계를 설명 |
| SQL·DB | JOIN과 집계를 직접 작성하고, 중복 때문에 값이 달라지는 사례를 재현 |
| 데이터 품질 | 오류를 고쳐 재제출하고, 재시도 전후 값이 유지됨을 확인 |
| 검색·AI | 관련 문서가 없는 질문을 만들고 실패 이유와 보류 조건을 설명 |
| 운영 | DB 연결 실패·중복 요청 등의 상황에서 결과와 복구 절차를 재현 |
| 지원 준비 | 도움 없이 작은 변경을 구현하고 테스트 추가, 기술 선택의 대안을 설명 |

SQL·API를 직접 수정하고 첫 프로젝트를 독립 실행하기 전에는 두 번째 프로젝트를 시작하지 않습니다. 자격증은 SQL·CS 학습과 목표 공고의 우대 조건을 보고 선택하며, 아직 확인하지 않은 시험 일정·응시 자격을 확정하지 않습니다.

## 실제 데이터로 바꿀 때

이용이 허용된 공개 데이터나 비식별화한 본인 데이터를 사용합니다. 원천 데이터에 배송 예정일·실제 배송일이 없으면 배송 지연 지표를 실제 데이터 성과로 주장하지 않습니다. 제공되는 컬럼으로 계산할 수 있는 주문·금액·취소 분석부터 적용하고, 합성 데이터 실험은 명확히 구분합니다.

AI 응답 평가에는 처음 보는 질문을 일부 남겨 두고, 평가 질문에 맞춰 검색 코드만 반복 수정해 얻은 높은 점수를 일반적인 정확도로 주장하지 않습니다. 응답시간과 비용도 실제 호출을 측정한 조건과 함께 기록합니다.

## 이력서에 남길 증거

프로젝트 목적, 본인이 맡은 변경, 비교한 대안, 재현 방법, 측정 결과, 실패와 수정 기록을 남깁니다. 현재 생성된 전체 코드를 모두 혼자 작성했다고 표현하지 않습니다. 아직 하지 않은 클라우드 운영·팀 협업·실사용 성과를 완료 실적으로 넣지 않습니다.

예를 들어 본인이 기간 필터를 구현했다면 경계 시각 테스트와 SQL을 연결해 설명합니다. 인덱스를 개선했다면 데이터 크기, 실행계획, 반복 측정 방식, 개선 전후 결과를 함께 제시합니다. 숫자는 측정한 뒤 채웁니다.
