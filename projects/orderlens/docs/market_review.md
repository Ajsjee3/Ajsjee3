### 개발 계획에 반영

OrderLens를 첫 프로젝트로 두고 공개 데이터 정제→전용 DB·재적재 방지→SQL 측정→배치 복구 순서로 진행합니다. 이후 직접 실행·수정·설명하는 기준을 통과하면 [OpenDART](https://opendart.fss.or.kr/intro/main.do)의 금융 공시 자료를 활용하는 두 번째 프로젝트를 검토합니다. 인증키 발급과 실제 API 호출, LLM 사용은 아직 하지 않았습니다.

학기·방학의 시간을 늘릴 수 있다고 가정하지 않고 주 6~10시간을 유지합니다. 첫 프로젝트를 시연할 수 있으면 2027년 초에도 인턴·현장실습의 지원 자격을 확인할 수 있습니다. 지원을 9월까지 일률적으로 미루지 않습니다. [커리큘럼 비교](../../../docs/curriculum_alignment.md)와 [월별 학습 계획](roadmap.md)에 반영했습니다.

## 결론과 적용 범위

첫 준비 방향으로 **Python 기반 AI 서비스 백엔드**를 제안하고, **데이터 엔지니어 인턴·주니어**를 함께 검토합니다. 데이터 분석은 이 프로젝트의 문제 정의·SQL·지표 설계 역량을 강화하는 축으로 둡니다. 이는 사용자의 AI 에이전트·데이터 분석 관심, FastAPI 학습 맥락, 아래 공고 요구사항을 연결한 판단입니다. 취업 확률을 계산한 결과는 아닙니다.

아래 표는 공개 원문을 확인할 수 있었던 **7개 회사의 공고 8건**을 목적에 맞게 고른 비교입니다. 상시채용 표기 7건과 마감 표기 1건을 구분했습니다. 검색어가 Python·AI·데이터에 치우쳐 있으므로 전체 국내 개발자 시장의 언어 비중, 직무별 채용 규모, 경쟁률을 대표하지 않습니다. 일반 Java/Spring 백엔드 시장 전체도 조사하지 않았습니다.

대부분 공고에 최초 게시일이 표시되어 있지 않습니다. 확인일에 페이지가 조회되었다는 사실과 새로 올라온 공고라는 사실은 다릅니다. 상시채용 표기만으로 실제 현재 접수 가능 여부를 확정하지 않았으며 지원 직전에 원문에서 다시 확인해야 합니다. **2027년의 채용 규모나 호준님의 합격 확률은 모르겠습니다.**

## 여기서 내린 판단

1. **AI 서비스를 만드는 역할과 모델 연구 역할을 구분해야 합니다.** 위 AI 서비스 공고는 Python 앱·RAG·API를 중심으로 설명하고, 연구·CV 사례는 석사·논문 또는 모델 전문성을 요구합니다. 모든 AI 공고가 석사를 요구한다고 일반화할 수는 없습니다.
2. **신입 표기도 기초적인 실무 증거를 요구합니다.** SQL·Python을 안다는 선언보다 정상·오류 입력을 다루는 동작, 테스트 결과, 지표 정의, 본인이 설명하는 설계가 도움이 될 것이라는 판단입니다.
3. **현재 학습을 연결할 수 있습니다.** FastAPI → DB → 적재·분석 → 검색·AI 응답 순서로 같은 제품을 확장하면 여러 도구를 배우는 이유가 구체적입니다.
4. **도구 나열을 프로젝트 목표로 삼지 않습니다.** Kafka·Spark·Kubernetes는 데이터 규모와 운영 문제가 생겼을 때 선택합니다. 초기에는 Python·SQL·API·테스트가 우선입니다.
