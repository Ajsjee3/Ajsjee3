# 제목·본문 검색 가중치 실험

## 문제

기존 BM25는 짧은 제목과 긴 본문을 같은 토큰 묶음으로 계산합니다. 제목이 문서의 주제를 요약하지만, 제목을 더 크게 반영하는 것이 실제 질문의 정답 문서와 보류 판단을 함께 개선하는지는 확인하지 않았습니다.

## 비교 방법

- 본문 가중치는 `1.0`으로 고정하고 제목 가중치 `1.0`, `1.5`, `2.0`, `3.0`을 비교합니다.
- 제목 가중치는 제목 토큰 빈도에 곱합니다. 별도 필드 길이 정규화를 구현한 완전한 BM25F는 아닙니다.
- 후보 선택에는 고정 평가와 문장·ID가 겹치지 않는 개발 질문 26개만 사용합니다.
- 각 후보에서 최소 점수도 개발 질문으로 다시 고르고, 정답 1위 수용률과 무관 질문 보류율의 평균을 비교합니다.
- 동률이면 정답 수용률, 더 작은 제목 가중치, 더 낮은 최소 점수 순으로 선택합니다.
- 고정 32문항은 후보 선택에 사용하지 않고, 개발 자료에서 선택된 한 후보를 현재 설정과 한 번 비교합니다.
- 고정 평가의 균형 성공률이 현재 설정보다 엄격하게 높을 때만 API 설정을 바꿉니다.

## 결과

개발 자료에서는 제목 `1.5`, 본문 `1.0`, 최소 점수 `4.186289`가 선택됐습니다. 개발 균형 정확도는 `0.90625`였습니다.

고정 평가에서 선택 후보의 Top-1은 `0.625 → 0.666667`로 올라갔지만 Recall@3은 `0.9375 → 0.895833`으로 낮아졌습니다. 잘못된 답변 가능 질문 수용은 `7 → 5`로 줄었지만 답변 가능 질문 보류가 `2 → 5`로 늘어, 보류 정책의 균형 성공률은 `0.75 → 0.729167`로 낮아졌습니다.

따라서 제목 가중치 `1.5`는 채택하지 않습니다. 실제 API는 제목 `1.0`, 본문 `1.0`, 최소 점수 `3.197979`를 유지합니다. 순위 지표 하나만 좋아졌다는 이유로 서비스 설정을 바꾸지 않습니다.

## 재현

```bash
python -m scripts.evaluate_retrieval_weights
```

후보별 개발 결과, 고정 평가의 현재 설정·선택 후보 결과, 실패 행과 채택 결정을 `artifacts/retrieval_field_weight_experiment.json`에 기록합니다.

## 한계

- 개발·고정 질문 모두 수작업이며 실제 사용자 로그나 독립 평가가 아닙니다.
- 문서는 10개뿐이며 다른 문서 집합에서 같은 가중치 결과를 기대할 수 없습니다.
- 제목 가중치 구현은 작은 비교 실험이며 Typesense의 검색 알고리즘이나 BM25F를 복제하지 않았습니다.
