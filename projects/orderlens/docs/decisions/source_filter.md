# 판매 경로별 지연 주문 조회

작성: 2026-09-09 · 버전: 0.1.1

## 요구사항

운영 담당자가 `market_a`의 지연 주문 20건을 요청하면 해당 경로의 주문이 최대 20건 나와야 합니다. 다른 경로의 주문이 더 오래 지연됐다는 이유로 조회 한도를 먼저 차지해서는 안 됩니다.

```text
GET /v1/orders/attention?source=market_a&limit=20&as_of=2026-09-08T00:00:00Z
```

## 선택

조회 순서는 다음과 같습니다.

1. 조회 시점보다 늦게 갱신된 버전을 제외합니다.
2. 판매 경로·주문 번호별로 최신 버전을 선택합니다.
3. 결제·배송 중 상태이며 배송 예정 시각이 지난 주문을 고릅니다.
4. 지정한 판매 경로를 필터링합니다.
5. 배송 예정 시각, 판매 경로, 주문 번호순으로 정렬하고 `limit`을 적용합니다.

응답을 만든 뒤 Python에서 경로를 걸러내면, 이미 조회 한도를 차지한 다른 경로 때문에 결과가 비는 경우가 생깁니다. 필터를 SQL 조건에 포함해 이 문제를 피했습니다.

입력과 조회에 같은 `OrderSource` 타입을 사용합니다. 허용 값은 `market_a`, `market_b`, `own_store`입니다. 필터를 생략하면 전체 경로를 조회하고, 잘못된 값은 422를 반환합니다. 정상적인 경로지만 해당 주문이 없으면 빈 배열을 반환합니다.

## 경계 사례

[test_attention.py](../../tests/test_attention.py)는 다른 경로가 더 일찍 지연된 경우에도 요청한 경로의 주문이 한도 안에 들어오는지 확인합니다. 같은 주문 번호를 두 경로에 넣고, 한쪽 주문만 취소해 최신 상태 선택과 경로 구분이 함께 유지되는지도 확인합니다.

배송 예정 시각이 조회 시각과 같으면 아직 지연이 아닙니다. 취소된 최신 버전 대신 예전 결제 상태가 다시 나타나서도 안 됩니다.

## 남은 범위

이 필터는 조회 편의 기능입니다. 사용자별 접근 권한은 공통 API 키와 별도로 설계해야 합니다. 페이지를 넘기는 기능은 아직 없으며, 같은 조건에서의 순서만 일정하게 유지합니다.
