# 자동화 범위와 다음 기능

## 지금 실행되는 자동화

`python -m scripts.check`를 실행하면 코드 검사 → 테스트 → SQLite 마이그레이션 왕복 → 합성 데이터 생성 → 임시 DB 적재·재전송 → 지표·근거 출력 → 검색 평가 → 실제 HTTP 시연이 순서대로 실행됩니다. 검사나 테스트가 실패하면 다음 단계로 진행하지 않습니다.

GitHub Actions 설정도 포함되어 있습니다. 저장소에 올리고 Actions가 허용된 환경이면 push·pull request·수동 실행에 맞춰 같은 검사를 수행하도록 구성했습니다. 원격 실행 상태는 Ajsjee3/Ajsjee3 저장소의 Actions 탭에서 확인합니다.

최근 채용 공고 검토일은 2026-10-26입니다. 원문과 모집 상태는 market_review.md에 기록했습니다. 반복 개발의 범위는 저장소 루트 docs/development_plan.md, 커리큘럼 비교는 docs/curriculum_alignment.md에 있습니다.

## 기능별 상태

| 기능 | 상태 | 다음에 검증할 내용 |
|---|---|---|
| FastAPI 입력 API | 구현·SQLite 검증 | OpenAPI 응답 모델을 더 구체화 |
| 데이터 검증·실패 행 기록 | 구현·검증 | 실제 원천 포맷 매핑·실패 원본의 안전한 보관 |
| UCI 공개 거래 정제 | 전체 CSV·반복 실행 검증 | 원본 제공처가 바뀔 때 해시·계약 재검토 |
| 공개 거래 전용 DB 적재 | 전체 SQLite·합성 PostgreSQL 검증 | 동시 첫 적재 경합·조회 API |
| 공개 거래 SQL 계획·인덱스 | 전체 SQLite 반복 측정·PostgreSQL 검사 구현 | cold-cache·다른 선택도·쓰기 비용 |
| 공개 거래 적재 시도 이력 | 강제 실패·복구·재실행 SQLite·PostgreSQL 검증 | 강제 종료·오래된 running·동시 첫 적재 |
| 버전 중복 방지·최신 상태 | 구현·검증 | PostgreSQL 동시 요청과 버전 간 계약 |
| SQL 운영 지표 | 실제 데이터 집계·SQLite 계획 비교 | 지표 정의 확장·PostgreSQL 전체 자료 |
| 상태별 주문 목록·페이지 조회 | 구현·SQLite 및 실제 HTTP 검증 | 동시 적재 중 일관성 정책, 큰 offset 성능 |
| BM25 문서 검색 | 별도 10문서·32질문·qrels와 실패 행 평가 | 고정 집합으로 보류 기준 비교 |
| 규칙 기반 요약 | 구현·검증 | 근거를 인용하는 LLM 응답 |
| Alembic 마이그레이션 | 네 리비전·SQLite 왕복 검증 | 기존 DB 기준점 연결·운영 전환 순서 |
| Docker·PostgreSQL 설정 | PostgreSQL 16.15 원격 통합 검증 | 로컬 Compose 실행·기존 DB 전환 |
| GitHub Actions | 0.8.0 일반·PostgreSQL 16.15 원격 검사 통과 | 의존성 갱신 때 경고·호환성 재검증 |
| 공개 배포·사용자 권한 | 후속 과제 | 배포 환경·예산·사용자별 데이터 분리 |
| 임베딩·벡터 DB·자율 에이전트 | 후속 과제 | 검색 기준선 비교·도구 권한·평가 |

## 구현 순서가 있는 작업 목록

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| 완료 | source별 지연 주문 필터 | 경로·최신 상태·시간 경계·조회 한도 API 검증 |
| 완료 | 상태별 주문 목록·페이지 처리 | 필터·정렬·경계·빈 결과·뒤늦은 적재의 한계 재현 |
| 완료 | PostgreSQL 통합 검증과 마이그레이션 | SQLite·PostgreSQL에서 마이그레이션 왕복과 핵심 데이터 흐름 확인 |
| 완료 | 실제 데이터 변환기 | 원본·정규화 필드 매핑, 오류 사유, 두 번의 전체 정제 결과 |
| 완료 | 공개 거래 DB 적재 | 별도 테이블·리비전, GBP 금액 정밀도, 파일 단위 재적재 방지 |
| 완료 | SQL 성능 비교 | 541,907행과 실행계획이 있는 동일 조건 측정, 인덱스 공간 기록 |
| 완료 | 적재 시도 관측·재실행 | 강제 실패 후 복구, 중복 없는 결과, 실패 기록 확인 |
| 완료 | 문서·검색 평가집합 확장 | 문서·질문·qrels 분리, 32질문 기준선과 실패 행 기록 |
| 1 | 근거 부족 질문 보류 | 고정 평가집합으로 점수 기준과 정답·오탐 변화 비교 |
| 2 | 임베딩 검색과 LLM 답변 | BM25와 검색 방식 비교, 문서 인용, 응답 평가 |
| 3 | 사용자 권한과 배포 | 접근권한 검사, HTTPS, 제한된 API 키, 운영 기록 |
| 4 | 사용자 피드백·팀 리뷰 | 실제 피드백 한 건을 기능 개선으로 연결한 기록 |

Kafka·Spark·Kubernetes를 추가하는 일은 현재 필수 과제로 두지 않습니다. 먼저 측정한 데이터 규모와 처리 문제가 그 기술을 요구하는지 설명할 수 있어야 합니다.
