# 자동화 범위와 다음 기능

## 지금 실행되는 자동화

`python -m scripts.check`를 실행하면 코드 검사 → 테스트 → SQLite 마이그레이션 왕복 → 합성 데이터 생성 → 임시 DB 적재·재전송 → 지표·근거 출력 → 검색 평가 → 실제 HTTP 시연이 순서대로 실행됩니다. 검사나 테스트가 실패하면 다음 단계로 진행하지 않습니다.

GitHub Actions 설정도 포함되어 있습니다. 저장소에 올리고 Actions가 허용된 환경이면 push·pull request·수동 실행에 맞춰 같은 검사를 수행하도록 구성했습니다. 원격 실행 상태는 Ajsjee3/Ajsjee3 저장소의 Actions 탭에서 확인합니다.

채용 공고 조사는 2026-09-08에 수행한 결과입니다. 이후 개발은 실제 공개 저장소와 새 공고를 함께 검토해 다음 기능을 정합니다. 반복 개발의 범위는 저장소 루트 docs/development_plan.md에 기록합니다.

## 기능별 상태

| 기능 | 상태 | 다음에 검증할 내용 |
|---|---|---|
| FastAPI 입력 API | 구현·SQLite 검증 | OpenAPI 응답 모델을 더 구체화 |
| 데이터 검증·실패 행 기록 | 구현·검증 | 실제 원천 포맷 매핑·실패 원본의 안전한 보관 |
| 버전 중복 방지·최신 상태 | 구현·검증 | PostgreSQL 동시 요청과 버전 간 계약 |
| SQL 운영 지표 | 구현·검증 | 실제 데이터의 지표 정의와 성능 |
| 상태별 주문 목록·페이지 조회 | 구현·SQLite 및 실제 HTTP 검증 | 동시 적재 중 일관성 정책, 큰 offset 성능 |
| BM25 문서 검색 | 구현·작은 예제 평가 | 별도 평가 질문·문서 확대 |
| 규칙 기반 요약 | 구현·검증 | 근거를 인용하는 LLM 응답 |
| Alembic 초기 마이그레이션 | 구현·SQLite 왕복 검증 | 기존 DB 기준점 연결·두 번째 리비전 |
| Docker·PostgreSQL 설정 | 통합 검사 구현·원격 실행 대기 | 실제 검사 통과 여부와 로컬 Compose 실행 |
| GitHub Actions | 0.2.0 원격 실행 확인 | 변경별 PR 검사와 실행 근거 확인 |
| 공개 배포·사용자 권한 | 후속 과제 | 배포 환경·예산·사용자별 데이터 분리 |
| 임베딩·벡터 DB·자율 에이전트 | 후속 과제 | 검색 기준선 비교·도구 권한·평가 |

## 구현 순서가 있는 작업 목록

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| 완료 | source별 지연 주문 필터 | 경로·최신 상태·시간 경계·조회 한도 API 검증 |
| 완료 | 상태별 주문 목록·페이지 처리 | 필터·정렬·경계·빈 결과·뒤늦은 적재의 한계 재현 |
| 진행 | PostgreSQL 통합 검증과 마이그레이션 | SQLite 검증 완료, PostgreSQL 원격 검사 대기 |
| 4 | 실제 데이터 변환기 | 원본·정규화 필드 매핑, 오류 비율, 재처리 결과 |
| 5 | SQL 성능 비교 | 데이터 크기와 실행계획이 있는 전후 측정 |
| 6 | 문서·검색 평가집합 확장 | 질문과 정답 문서의 별도 검토, 미사용 평가 질문 확보 |
| 7 | 임베딩 검색과 LLM 답변 | 검색 방식 비교, 문서 인용, 근거 부족 시 답변 보류 |
| 8 | 주기 배치·관측·재시도 | 강제 실패 후 복구, 중복 없는 결과, 실패 알림의 확인 |
| 9 | 사용자 권한과 배포 | 접근권한 검사, HTTPS, 제한된 API 키, 운영 기록 |
| 10 | 사용자 피드백·팀 리뷰 | 실제 피드백 한 건을 기능 개선으로 연결한 기록 |

Kafka·Spark·Kubernetes를 추가하는 일은 현재 필수 과제로 두지 않습니다. 먼저 측정한 데이터 규모와 처리 문제가 그 기술을 요구하는지 설명할 수 있어야 합니다.
