# 기여와 개발 기록

변경은 문제와 기대 결과를 먼저 정리한 뒤 구현합니다. 데이터 처리 결과가 달라지는 변경에는 재현 입력과 검증 결과를 함께 남깁니다.

```bash
python -m scripts.check
```

커밋 메시지는 `feat:`, `fix:`, `docs:`, `refactor:` 등의 접두사 뒤에 바뀐 동작을 적습니다. 한 변경에는 같은 목적의 코드·테스트·문서를 묶고, 작업 브랜치와 PR에 이유·검증·한계를 남깁니다. 필요한 검증이 통과하고 충돌이 없는 작은 변경을 main에 반영합니다. 설계 선택이 있으면 `docs/decisions` 등에 이유와 남은 제약을 기록합니다. 성능 수치는 데이터 크기·환경·실행 명령을 함께 남긴 경우에 사용합니다.

매 PR에는 시작 main SHA·검토일, 누적 8개 영역의 상태와 근거, 취업 근거가 공개된 개발자 약 2명의 현재 파일·SHA·변경 이력 비교를 남깁니다. 비교 자료 접근 실패는 미완료로 표시합니다. 구현·실행·운영·본인 이해도를 구분하고, 중요한 회귀와 격차 한 가지를 우선 보완합니다. `docs/portfolio_review.md`를 갱신하고 계획·개발 기록과 연결합니다. 필수 검증 실패·미실행 또는 중요한 결함이 있으면 병합하지 않습니다.

초기 구현과 문서 정리에는 Codex를 활용했습니다. v0.1.0~0.12.0의 코드 작성·실행 검증은 Codex 작업이며, 이후 직접 수정하고 확인한 내용은 `docs/learning_log.md`에 별도로 기록합니다.
