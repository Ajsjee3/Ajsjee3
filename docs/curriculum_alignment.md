# 커리큘럼 비교와 프로젝트 선택

검토일: 2026-09-22. 호준님이 이 대화에 붙여 주신 「컴공 2027 취업시장」 본문 전체와 현재 저장소를 비교했습니다. 원래 화면의 체크리스트·월별 표 중 복사되지 않은 항목은 복원했다고 간주하지 않았습니다.

## 결정

**OrderLens를 첫 데이터·백엔드 프로젝트로 완성하고, 직접 실행·수정·설명할 수 있게 된 뒤 FinInsight를 두 번째 프로젝트로 검토합니다.** Python·SQL·DB·API라는 공통 기반은 두 계획이 같습니다. 현재 프로젝트를 주가 서비스로 다시 만드는 것보다 실제 데이터 처리와 복구 경험을 채우는 편이 주 6~10시간 범위에 맞습니다.

금융 IT가 주력이 되면 두 번째 프로젝트의 범위를 Java/Spring 모의 거래 시스템으로 바꿀 수 있습니다. 금융 데이터를 Python으로 다뤘다는 사실만으로 계정계·거래 시스템 개발 역량을 갖췄다고 표현하지 않습니다.

| 비교 항목 | 기존 OrderLens 계획 | 제공된 대화의 계획 | 이번 조정 |
|---|---|---|---|
| 공통 기초 | Python·SQL·FastAPI와 CS | Python·SQL 후 DB·백엔드 | 유지; 프레임워크보다 작은 입력의 흐름부터 복습 |
| 첫 프로젝트 | 주문 상태·중복·집계 API | FinData: 주가 수집·저장·통계 API | OrderLens 유지, 공개 거래 자료의 정제·DB 적재 추가 |
| 두 번째 프로젝트 | 같은 프로젝트에 검색·AI 확장 | FinInsight: 공시 수집·분석 후 RAG | 첫 프로젝트의 학습 기준 통과 후 선택; 지금은 새 저장소를 만들지 않음 |
| 시간 | 주 6~10시간 | 학기 10~12시간, 방학 20~25시간 가정 | 확인된 6~10시간 유지; 방학 증량을 전제하지 않음 |
| 지원 시점 | 2027년 9월 중심 | 2027년 초부터 인턴·현장실습 확인 | 첫 시연이 가능해지면 지원 자격을 확인; 두 프로젝트 완성을 기다리지 않음 |
| 금융 IT | 별도 분기 부족 | Java/Spring·트랜잭션·동시성 | 주력 확정 시 두 번째 프로젝트를 대체; 세 번째 대형 프로젝트를 더하지 않음 |
| 진척 판단 | 구현 기록 중심 | 직접 구현·설명 가능 여부 | 코드의 완료와 호준님의 학습 완료를 별도로 기록 |

## 첫 프로젝트가 같은 역량을 보여 주나요?

| FinData에서 제안한 역량 | OrderLens의 현재 증거 | 아직 필요한 것 |
|---|---|---|
| 외부 자료 수집·검증 | [UCI CSV 다운로드·정제](../projects/orderlens/docs/public_retail.md), 오류 격리와 출처 해시 | 증분 API 수집, 실패 후 재개 |
| 중복 방지·트랜잭션 | 주문 버전과 공개 거래 파일의 UNIQUE·충돌 처리, 재전송·롤백 테스트 | 동시 프로세스의 최초 적재 경합과 실패 후 재개 |
| PostgreSQL·마이그레이션 | 두 리비전과 PostgreSQL 합성 입력 통합 검사 | 전체 공개 거래의 PostgreSQL 적재와 운영 전환 절차 |
| 조회 API·SQL | 상태·판매 경로 필터, 페이지 처리, 최신 주문 집계 | 공개 거래의 기간별 집계; 주가·종목 API는 구현하지 않음 |
| 수집 이력·데이터 품질 | 배치 오류 기록, 정제 결과·입출력 해시 | 주기 실행과 복구 상태 관리 |
| 테스트·실행 안내 | 자동 검사, 실제 HTTP 재현, 공개 데이터 정제 결과 | 호준님의 독립 실행·작은 수정, 간단한 조회 화면과 실제 피드백 |

주문 자료에는 주가·거래소·재무제표가 없습니다. 따라서 FinData의 금융 도메인 경험까지 대체한 것은 아닙니다. 데이터 파이프라인과 백엔드 기초를 먼저 확보한다는 목적에서 첫 프로젝트를 대응시켰습니다.

## 채용 자료와 연결한 판단

2026-09-22에 직접 확인한 [공고·통계 원문과 한계](../projects/orderlens/docs/market_review.md)를 근거로 삼았습니다. 노타의 ICT 인턴 계획은 Python·REST·SQL·Git과 데이터 처리, 오렌지스퀘어 데이터 엔지니어 인턴은 프로그래밍·SQL·ETL/ELT 이해를 요구합니다. 우리은행의 마감된 2026 하반기 IT개발 공고는 금융 시스템 개발에 C·Java·SQL 등의 역량을 제시합니다. 이는 공통 기반을 먼저 만들고 금융 IT를 별도 분기로 두는 근거입니다.

대화에 나온 전체 공고 +10%, AI·개발·데이터 -4%는 잡코리아가 2026-07-03에 발표한 자사 플랫폼의 상반기 전년 대비 공고 증감률로 확인했습니다. 채용 인원·취업 성공률·2027년 전망치가 아닙니다. 소수 공고로 어느 직무가 더 쉽게 취업되는지도 판단하지 않습니다.

## 앞으로의 구현과 학습

공개 거래 CSV 정제와 전용 DB 적재, 파일 단위 재적재 방지까지 구현했습니다. 다음은 같은 541,907행에서 SQL 실행계획과 집계를 검증하고, 그다음 배치 재시도·복구를 다룹니다. 데이터가 안정적으로 처리되기 전에 AI 기능부터 늘리지 않습니다.

2027년 2월에 첫 프로젝트를 직접 설명하고 수정할 수 있는지 확인합니다. 통과하고 데이터·AI 방향을 유지하면 OpenDART 기반 FinInsight를 작게 시작합니다. 원본 보관, 기간·통화·단위 정규화, 수집 이력부터 만들고 SQL 수치와 문서 근거를 연결하는 검색은 뒤에 추가합니다. API 키나 유료 모델 사용은 아직 실행하지 않았습니다.

아래는 학습 과제이며 완료 기록이 아닙니다. 현재 학습 상태는 `not_assessed`입니다.

- [ ] CSV 한 행이 `normalize_record`를 거쳐 어떤 값이 되는지 설명하기
- [ ] 취소 표시와 음수 수량을 함께 보존하는 이유 설명하기
- [ ] GBP 0.001을 정수 원화 금액으로 바꾸면 잃는 정보 확인하기
- [ ] 잘못된 날짜 입력 하나를 직접 추가하고 테스트 결과 설명하기
- [ ] 작은 표의 GROUP BY 결과를 손계산한 값과 비교하기
- [ ] 도움 없이 실행한 명령과 직접 수정한 부분만 학습 기록에 남기기

월별 제안과 주간 시간 배분은 [학습 로드맵](../projects/orderlens/docs/roadmap.md)에 정리했습니다. 졸업·입사 가능 시기는 미확인이라 2027년 정규직 입사를 확정 일정으로 두지 않습니다.
